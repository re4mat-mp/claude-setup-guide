**Agents are born restricted (read-only or draft-only) and earn permissions by training.** The key is not time or trust; it is having the traps of that craft written into the agent's own charter. A permission without the traps written down is an agent that will repeat our mistake with more reach.

**The case:** a data agent started read-only. It graduated to read-and-build after three dispatches in one day with results that were used, and after five API traps it had hit were written into its charter: a partial update that erases omitted fields, a format change that wipes the query, overlapping cards that raise no error, IDs that change when items move. The real trigger was a task that had to run half-delegated and half by hand, because the analysis could be dispatched and the writes could not. The graduated charter also got a write contract: back up before each structural write, verify by running both the card and the dashboard, check for dependents before deleting.

**Why:** the permission matters because the charter now contains what is needed not to repeat the error. It is not a reward for the past.

**How to apply:**
- New agents start read-only (researchers, reviewers) or draft-only (writers). Draft means a human or the main session does the sending.
- Graduate when both hold: (1) the craft has been exercised several times with shipped results; (2) its traps are written in the charter. If (2) is missing, the next step is writing the traps, not granting the permission.
- Some gates no permission touches: merges, sending to people, irreversible production actions.
- Announce a graduation in the same turn, with exactly what it enables.
- An agent that never gets dispatched never graduates, however much its craft gets used. Dispatch it.
